Design principles.

Kernel-object access requires a capability; files, network, devices and graphics are isolated userspace services; the boot chain is verifiable layer by layer.

01

No implicit rights

Every kernel-object access names a capability, a type and rights explicitly.

02

Userspace is the system

Files, network, devices and graphics are isolated from each other and cooperate via IPC.

03

Reproducible end-to-end

Build and boot steps are repeatable; every step from bootloader to desktop produces an independent artifact.

Boot sequence.

From the reset vector, exception levels hand over one by one up to the graphical desktop.

  1. 01 / EL3

    Bootloader

    Platform init, image load.

  2. 02 / EL2

    Hypervisor

    Stage-2 tables and virtual interrupts.

  3. 03 / EL1

    Microkernel

    Takes over capability, IPC and scheduling.

  4. 04 / EL0

    SystemDaemon

    Creates processes, memory and namespaces.

  5. 05 / EL0

    Framework

    Launches independent userspace services.

  6. 06 / APP

    Applications

    A full graphical desktop comes up.

The kernel boundary.

EL1 keeps: capability objects, IPC endpoints, timers and exception entry.

Object-capability

A 64-bit cref locates a CNode slot; object type and rights mask authorize together.

Migrating-thread IPC

The caller's execution context migrates into the callee's address space — no queue wake-up.

Schedule / execute split

Scheduling metadata and register state are separate; each CPU schedules independently.

Service interface generation

.idl generates client, server, transport structs and ABI validation.
