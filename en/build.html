Flashing the image.

Writing to the wrong disk will overwrite other media — confirm the device at every step.

MACOS

diskutil + dd

After inserting the SD card or exposing CM4 eMMC in mass-storage mode:

diskutil list
diskutil unmountDisk /dev/diskN
sudo dd if=tranquil-cm4.img \
  of=/dev/rdiskN bs=4m \
  status=progress conv=sync
sync && diskutil eject /dev/diskN
LINUX

lsblk + dd

Write to the whole-disk device, never a partition node (e.g. sdX1):

lsblk
sudo umount /dev/sdX*
sudo dd if=tranquil-cm4.img \
  of=/dev/sdX bs=4M \
  status=progress conv=fsync
sync
RPIBOOT

Direct eMMC write

Set the USB boot jumper on the CM4 IO board, connect the host to the USB slave port:

Image partitions & layout.

boot.img (64MB)
  offset 0      Bootloader    8MB
  offset 2048   DTB           8MB
  offset 4096   Hypervisor   16MB
  offset 8192   Kernel       16MB
  offset 12288  SystemDaemon  8MB
  offset 14336  Ramdisk cpio  8MB
vendor.img (32MB, ext2)
  bin/  driver daemons (.drv)
  etc/  drivers.json

system.img (128MB, ext2)
  zygote · framework services
  system UI · app ELFs

user.img (64MB, ext2)
  user-data template: sample music
  · pictures · games · AI config
boot.imgno partition table; loaded at the fixed offsets above
vendor / system / userext2 partition images (mke2fs + debugfs)
raw disk imagefour partitions — FAT32 boot + ext2 vendor + ext2 system + ext2 user — assembled by make_all_img.sh
CM4 boot partitionRaspberry Pi firmware + boot.img + DTB

make_boot_img.sh assembles boot.img via objcopy + dd at the offsets above; make_system_img.sh / make_user_img.sh build the ext2 partition images; make_all_img.sh writes all four partitions into the raw disk image.

Toolchain.

TOOLCHAIN

Cross compiler

Output is freestanding AArch64 binaries. Download a toolchain from newos.org/toolchains into the repository's toolchains/; the default is aarch64-elf (GCC 12.2.0).

MACOS ONLY

e2fsprogs

system.img is an ext2 image; assembling it on macOS requires Homebrew e2fsprogs.

brew install e2fsprogs

Note: source env_setup.sh in every new shell; OS_BASE_DIR is fixed at ~/kernel — edit it if you checked the repo out elsewhere.
