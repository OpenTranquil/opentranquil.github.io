Object-Capability Microkernel · AArch64

面向 AArch64 的 object-capability微内核操作系统。

EL1 仅保留调度、IPC 与异常；进程、内存、文件、网络、设备与图形均为隔离的用户态服务，经 capability 与 IPC 协作。

设计原则。

访问内核对象必须给出 capability；文件、网络、设备与图形为隔离的用户态服务；启动链逐层可独立验证。

01

没有隐式权限

访问任何内核对象，都要同时给出能力、类型与权限。

02

用户态是系统主体

文件、网络、设备与图形各自隔离，由 IPC 协作。

03

端到端可复现

构建与启动可重复执行；从 bootloader 到桌面的每一步都有独立产物。

启动序列。

从复位向量开始，异常级逐层交接至图形桌面。

  1. 01 / EL3

    Bootloader

    平台初始化，装载镜像。

  2. 02 / EL2

    Hypervisor

    建立 stage-2 与虚拟中断。

  3. 03 / EL1

    Microkernel

    接管 capability、IPC 与调度。

  4. 04 / EL0

    SystemDaemon

    创建进程、内存与命名空间。

  5. 05 / EL0

    Framework

    启动独立用户态服务。

  6. 06 / APP

    Applications

    进入完整图形桌面。

内核边界。

EL1 只保留：capability 对象、IPC 端点、定时器与异常入口。

Object-capability

64 位 cref 定位 CNode slot；对象类型与 rights mask 共同授权。

迁移线程 IPC

调用方执行上下文直接迁入被调地址空间，避开消息队列唤醒。

调度/执行上下文分离

调度元数据与寄存器状态分离；每个 CPU 独立调度。

服务接口代码生成

.idl 生成客户端、服务端、传输结构与 ABI 校验。
