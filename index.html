AArch64 · Object-Capability · Userspace Services

一个从引导到图形桌面完整实现的微内核操作系统。

TranquilOS 以 capability 作为统一授权模型：EL1 微内核只负责调度、IPC、异常与对象分发，进程、内存、文件系统、网络、窗口合成等全部系统能力都由边界清晰的用户态服务承担。覆盖 EL2 Type-1 hypervisor 到 14+ 图形应用的完整工程。

Design Pillars

三个贯穿全系统的决定。

TranquilOS 不是内核玩具，而是一次对「微内核 + capability 授权 + 用户态服务」组合在 AArch64 上的完整验证。

CAPABILITY

对象化授权，没有隐式权限

进程持有的是 CNode 中的 capability slot，而不是全局特权。访问 VSpace、Endpoint、Timer、Futex、IRQ 都需 typed capability，方法分发前检查 rights mask。

USERSPACE

用户态是系统主体

进程管理、物理内存分配、IPC 命名空间由特权 EL0 进程 SystemDaemon 承担；窗口、文件、网络、设备、应用生命周期是独立服务，故障域与职责边界一一对应。

END-TO-END

端到端的实现路径

从 bootloader、DTB、hypervisor、kernel 到 zygote、framework services、图形应用，每一阶段都有明确的镜像位置、初始化职责与交接对象，全部可从源码复现。

Boot Chain

启动链：六个阶段，每步职责单一。

01Bootloader

早期平台初始化、设备树解析与镜像装载；按 CPU CurrentEL 选择直入 EL1 内核，或先起 EL2 hypervisor。

02Hypervisor

EL2 Type-1：stage-2 地址转换、VM/VCPU/PCPU 生命周期、vGIC、vTimer、vPMU 与 hypcall 接口。

03Microkernel

EL1：capability 对象分发、迁移线程 IPC、SMP 调度、IRQ、timer、futex、upcall、模块与低层驱动。

04SystemDaemon

特权 EL0 进程：进程/线程创建、ELF 装载、物理页分配、SHM 映射、endpoint 命名空间、VM 管理。

05Framework

init → zygote 拉起 windowmgr、fsmgr、netmgr、devmgr、appmgr 等服务，全部经 SHM+IPC 互联。

06Applications

systemui、launcher、settings、files、monitor、music、whiteboard、nes、ai 等应用运行于同一服务边界之上。

Kernel Decisions

核心机制围绕隔离性、调用延迟与接口可维护性设计。

CAP

Object-capability

seL4 启发的对象能力模型。cref 为 64 位引用：高 32 位 cnode ID，低 32 位 slot。CNode 用 directory array 实现线性索引与无拷贝扩展。

IPC

迁移线程 IPC

同步调用不经消息队列唤醒服务线程，调用方执行上下文直接迁入被调地址空间；endpoint pool 横向扩展服务端并发。

SMP

调度/执行上下文分离

scontext 与 xcontext 拆分：per-CPU scheduler 只操作调度元数据，真正切换时才触碰寄存器状态；CFS 以可加载内核模块实现。

IDL

服务接口代码生成

.idl 描述服务接口，生成 client wrapper、server dispatch、传输结构体与 ABI 校验；persistent SHM 参数让固定控制结构复用映射。

Coverage

实现覆盖内核、虚拟化、服务、图形、网络与工具链。

内核核心

异常模型、MMU、SMP per-CPU 调度、capability 分发、迁移线程 IPC、fastcall、upcall、futex、IRQ、高精度 timer、模块系统、perf 追踪。

虚拟化

EL2 Type-1 hypervisor：stage-2 页表、VM/VCPU/PCPU 生命周期、vGIC、vTimer、vPMU、hypcall。

系统服务

SystemDaemon 四组件（procmgr/memmgr/ipcmgr/virtmgr）+ windowmgr、fsmgr、netmgr、devmgr、appmgr、audiomgr、fontmgr、statemgr、timemgr、agentmgr 等框架服务。

图形与应用

800×480 横屏画布，LVGL + FreeType + PortableGL 图形栈；14+ 用户应用运行于窗口合成器之上。

存储与网络

VFS 抽象 rootfs、ext2、FAT32、procfs、sysfs；lwIP TCP/IP 协议栈，mbedTLS 支持 HTTPS。

工具链

GN/Ninja 构建全部 ELF 与镜像；IDL 生成器消除服务胶水代码；四套平台脚本覆盖 QEMU 与树莓派真机。

Run It

从源码到可启动镜像，一条命令。

安装 aarch64-elf 交叉工具链后，运行脚本会完成 GN/Ninja 构建、boot.img 与 system.img 组装，并启动 4 核 SMP、2G 内存、带 VirtIO 与 ramfb 显示的 QEMU 虚拟机。
