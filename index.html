从引导到桌面，完整实现的微内核系统。

Capability 是唯一授权。EL1 只保留调度、IPC 与异常；其余系统运行在隔离的用户态服务中。

查看架构 → 从源码构建

三条原则。

01

没有隐式权限

访问任何内核对象，都要同时给出能力、类型与权限。

02

用户态是系统主体

文件、网络、设备与图形各自隔离，由 IPC 协作。

03

端到端可复现

从 bootloader 到桌面，每一层都能独立定位与验证。

六步，从上电到桌面。

  1. 01 / EL3

    Bootloader

    平台初始化，装载镜像。

  2. 02 / EL2

    Hypervisor

    建立 stage-2 与虚拟中断。

  3. 03 / EL1

    Microkernel

    接管 capability、IPC 与调度。

  4. 04 / EL0

    SystemDaemon

    创建进程、内存与命名空间。

  5. 05 / EL0

    Framework

    启动独立用户态服务。

  6. 06 / APP

    Applications

    进入完整图形桌面。

四个机制，定义内核边界。

CAP / 01

Object-capability

64 位 cref 定位 CNode slot；对象类型与 rights mask 共同授权。

IPC / 02

迁移线程 IPC

调用方执行上下文直接迁入被调地址空间，避开消息队列唤醒。

SMP / 03

调度/执行上下文分离

调度元数据与寄存器状态分离；每个 CPU 独立调度。

IDL / 04

服务接口代码生成

.idl 生成客户端、服务端、传输结构与 ABI 校验。

从 EL2 到应用层，全部可运行。

EL2

虚拟化

Type-1 · stage-2 · vGIC · vTimer · hypcall

EL1

内核核心

异常 · MMU · SMP · IPC · IRQ · timer · futex

EL0

系统服务

进程 · 内存 · 文件 · 网络 · 设备 · 窗口

APP

图形与应用

LVGL · FreeType · PortableGL · 14+ applications
