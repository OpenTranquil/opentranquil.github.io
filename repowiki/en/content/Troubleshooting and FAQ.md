## Deliverables

The website download page exposes two image entries:

- `downloads/tranquil-virt.img`: points to `kernel/out/tranquil-virt.img` for QEMU Virt.
- `downloads/tranquil-cm4.img`: points to `kernel/out/tranquil-cm4.img` for Raspberry Pi Compute Module 4.

The website repository exposes these files as symlinks. The real images are generated by platform scripts under `/Users/neo/kernel/out`.

## QEMU Virt Deployment

The recommended source-root entry point is:

```bash
./run_qemu_virt.sh
```

It builds the code, creates boot/system/user images, combines the raw disk image, and starts QEMU. The final raw image is `out/tranquil-virt.img` with boot, system, and user partitions.

Typical uses:

- local validation of the kernel, SystemDaemon, base services, and OS framework;
- regression testing of boot flow, image layout, application packaging, and SystemUI;
- debugging serial logs, QEMU monitor behavior, virtio block, and ramfb display.

## CM4 Deployment

The recommended CM4 entry point is:

```bash
./run_board_cm4.sh
```

It calls `platform/CM4/scripts/flash.sh`:

1. Generate `out/tranquil-cm4.img`.
2. Use `rpiboot` to expose the CM4 as USB mass storage.
3. Detect the newly attached external removable disk with `diskutil`.
4. Write the raw image with `sudo dd bs=1m conv=notrunc`.
5. Eject the disk.

Always verify the target disk number before CM4 flashing. Writing to the wrong disk can overwrite the host or another external drive.

## Release Checklist

Before publishing images, check:

- kernel version macros in `sys/BUILD.gn`;
- OS version macros in `os/BUILD.gn`;
- QEMU Virt boots into user-space services;
- CM4 image has been flashed or at least structurally inspected;
- website download page, repowiki flashing page, and actual image filenames match.

## Common Issues

| Issue | First checks |
| --- | --- |
| QEMU has no output | serial backend, PL011, boot-image offsets, DTB path |
| system image creation fails | `mke2fs` path, `images/system` contents, whether ELF outputs exist |
| application missing | `os/BUILD.gn` deps and `make_system_img.sh` copy list |
| CM4 not detected | `rpiboot`, USB cable, power, boot mode |
| risk of flashing wrong disk | `diskutil list`, detected `/dev/diskN`, raw `/dev/rdiskN` target |

## Operational Rules

- Image scripts are the source of truth; website and wiki instructions must follow them.
- Public images should be checked beyond file existence: inspect the partition table and key files.
- Scripts using `dd` must keep explicit disk-detection and confirmation behavior.
- QEMU and board deployment paths should remain separate so virtual-platform flags are not applied to hardware.
