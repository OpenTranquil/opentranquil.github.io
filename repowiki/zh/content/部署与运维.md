## 交付物

当前网站下载页提供两个镜像入口：

- `downloads/tranquil-virt.img`：指向 `kernel/out/tranquil-virt.img`，用于 QEMU Virt。
- `downloads/tranquil-cm4.img`：指向 `kernel/out/tranquil-cm4.img`，用于 Raspberry Pi Compute Module 4。

这两个文件在网站仓库中以符号链接形式暴露，实际镜像由 `/Users/neo/kernel/out` 下的平台脚本生成。

## QEMU Virt 部署

推荐使用源码根目录下的：

```bash
./run_qemu_virt.sh
```

该脚本完成构建、boot/system/user 镜像制作、raw 镜像合成和 QEMU 启动。最终 raw 镜像为 `out/tranquil-virt.img`，包含 boot、system、user 三个分区。

典型用途：

- 开发者本地验证内核、SystemDaemon、基础服务和 OS framework。
- 回归测试启动链路、镜像布局、应用打包和系统 UI。
- 调试串口日志、QEMU monitor、virtio block 和 ramfb 显示路径。

## CM4 部署

CM4 推荐入口为：

```bash
./run_board_cm4.sh
```

脚本会调用 `platform/CM4/scripts/flash.sh`：

1. 生成 `out/tranquil-cm4.img`。
2. 通过 `rpiboot` 让 CM4 进入 USB mass storage 模式。
3. 使用 `diskutil` 检测新出现的外部可移动磁盘。
4. 使用 `sudo dd bs=1m conv=notrunc` 写入 raw 设备。
5. 写入完成后弹出磁盘。

执行 CM4 烧录前必须确认目标磁盘编号，避免覆盖宿主机磁盘或其他外置存储。

## 版本与发布检查

发布镜像前建议确认：

- `sys/BUILD.gn` 中 kernel version 是否符合预期。
- `os/BUILD.gn` 中 OS version 是否符合预期。
- QEMU Virt 镜像可以启动到用户态服务。
- CM4 镜像已经完成至少一次实际烧录或镜像结构检查。
- 网站下载页、repowiki 下载烧录页和实际镜像文件名一致。

## 常见问题

| 问题 | 优先检查 |
| --- | --- |
| QEMU 无输出 | 串口后端、PL011、boot image 偏移、DTB 路径 |
| system image 创建失败 | `mke2fs` 路径、`images/system` 内容、ELF 是否已生成 |
| 应用缺失 | `os/BUILD.gn` 依赖、`make_system_img.sh` 复制列表 |
| CM4 未识别 | `rpiboot`、USB 线缆、供电、Boot 模式 |
| 烧录到错误磁盘风险 | `diskutil list`、脚本检测到的 `/dev/diskN`、是否使用 raw `/dev/rdiskN` |

## 运维原则

- 镜像生成脚本是事实来源，网站下载说明和文档必须跟随脚本更新。
- 对外分发镜像前不要只检查文件存在，应至少验证分区表和关键文件。
- 涉及 `dd` 的脚本必须保持显式磁盘确认逻辑。
- QEMU 和实体板卡的部署路径应分开说明，避免把虚拟平台参数误用于实机。
