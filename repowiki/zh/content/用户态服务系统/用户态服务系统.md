## 定位

TranquilOS 的系统能力主要由用户态服务组合完成。EL1 内核提供 Capability、IPC、地址空间、调度和中断等机制；EL0 的 `SystemDaemon`、`Init`、`Devmgr`、`Fsmgr`、`Zygote` 和 OS framework 服务负责进程、设备、文件系统、窗口、应用、输入、音频、字体、状态、时间等系统策略。

当前 OS 版本宏在 [os/BUILD.gn](file://os/BUILD.gn) 中定义为 `1.8.43`。

## 启动层级

```text
Kernel
  -> SystemDaemon
     -> Init
     -> Devmgr
     -> Fsmgr
     -> Idle
     -> Zygote
        -> framework services
        -> SystemUI
        -> applications
```

`SystemDaemon` 位于 `sys/kernel/systemd`，虽然源码目录在内核树下，但它是 EL0 根系统进程。它包含内存管理、进程管理、虚拟内存管理、IPC 管理、名称服务、ramdisk 加载和 capability helper 等模块，并通过 IDL 生成 systemd IPC 与 name service 的服务端/客户端代码。

## 基础用户态程序

[sys/uapps/BUILD.gn](file://sys/uapps/BUILD.gn) 当前构建四个基础用户态目标：

| 目标 | 路径 | 职责 |
| --- | --- | --- |
| `Idle` | `sys/uapps/base/idle` | 空闲进程，提供调度兜底执行流 |
| `Init` | `sys/uapps/base/init` | 用户态初始化入口，启动后续基础服务 |
| `Devmgr` | `sys/uapps/core/devmgr` | 设备管理与设备服务化 |
| `Fsmgr` | `sys/uapps/core/fsmgr` | 文件系统管理、会话、文件描述符表、VFS/rootfs/sysfs/procfs 等基础能力 |

这些目标会被 QEMU Virt 和 CM4 镜像脚本放入 ramdisk 或 system image，作为系统启动早期必须可用的服务。

## OS 基础服务与框架服务

`os/BUILD.gn` 在基础 UAPPS 之上构建完整用户态环境：

- `os/base/zygote`：应用和服务派生基础。
- `os/base/netmgr`：网络管理。
- `os/base/btmgr`：蓝牙管理。
- `os/framework/appmgr`：应用生命周期与 bundle 管理。
- `os/framework/windowmgr`：窗口、合成和显示组织。
- `os/framework/audiomgr`：音频服务。
- `os/framework/fontmgr`：字体服务。
- `os/framework/mmimgr`：多模态输入管理。
- `os/framework/statemgr`：系统状态服务。
- `os/framework/timemgr`：时间服务。
- `os/framework/agentmgr`：Agent 管理。

系统 UI 与应用包括 BootAnimation、Status、Nav、Lock、Launcher、Cursor、Overlay，以及 AI、Calendar、Calculator、Clock、Files、Memo、Monitor、Music、Nes、Settings、Whiteboard 等应用。

## 服务通信

用户态服务通过 IPC、Capability 和 generated IDL wrapper 通信。`SystemDaemon` 提供初始资源与命名服务，其他服务通过 name service 查找端点并建立调用关系。这个模型减少了全局共享状态，使服务权限可以按端点和 Capability 精确传递。

## 维护建议

- 新增系统服务时，应在 `os/BUILD.gn` 或 `sys/uapps/BUILD.gn` 中明确依赖关系。
- 需要早期启动的服务应进入 ramdisk 或 boot image 相关脚本；普通应用应进入 system image。
- 修改 service IDL 后，需要确认 `tools/idl_gen_action.py` 生成的 wrapper 被正确纳入 GN target。
- 服务间新增能力传递时，应同步审视 CNode 权限、IPC 端点所有权和失败恢复流程。
