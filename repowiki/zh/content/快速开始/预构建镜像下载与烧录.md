## 适用范围

本文说明如何使用网站提供的 TranquilOS 预构建镜像进行快速验证。镜像面向两类目标环境：QEMU virt 虚拟平台和 Raspberry Pi Compute Module 4。若需要修改内核、系统服务、驱动或应用，仍建议从源码重新构建；若目标是验证启动链、图形会话、用户态服务和应用层功能，可优先使用预构建镜像。

## 镜像清单

| 镜像 | 目标平台 | 典型用途 |
| --- | --- | --- |
| `tranquil-virt.img` | QEMU virt · AArch64 | 在桌面主机上验证 bootloader、EL2 hypervisor、EL1 kernel、SMP、ramfb 图形输出、VirtIO 设备和用户态服务。 |
| `tranquil-cm4.img` | Raspberry Pi Compute Module 4 | 在真实硬件上验证 CM4 启动、HDMI 输出、串口日志、eMMC/SD 写入路径和外设初始化。 |

镜像可从网站下载页获取：

- `downloads/tranquil-virt.img`
- `downloads/tranquil-cm4.img`

当前网站下载入口使用本地构建产物作为分发源：

- `/Users/neo/kernel/out/tranquil-virt.img`
- `/Users/neo/kernel/out/tranquil-cm4.img`

## 磁盘结构

两个镜像都是 raw disk image，不是单一 kernel 或 boot image。QEMU virt 镜像由 `platform/QemuVirt/scripts/make_all_img.sh` 生成，CM4 镜像由 `platform/CM4/scripts/make_all_img.sh` 生成。二者都采用三分区模型：

| 分区 | 文件系统 | 内容 |
| --- | --- | --- |
| P1 | FAT32 | `boot.img`；CM4 镜像还包含 firmware 和 `bcm2711-rpi-cm4.dtb`。 |
| P2 | ext2 | `system.img`，包含 zygote、framework services、system UI 和应用 ELF。 |
| P3 | ext2 | `user.img`，包含用户数据模板、音乐、图片、NES ROM 和 AI 配置。 |

## 完整性校验

镜像文件较大，下载、复制或烧录过程中可能出现截断。建议在分发目录生成 SHA-256 摘要，并在目标主机写入前再次校验。

```bash
shasum -a 256 downloads/tranquil-virt.img
shasum -a 256 downloads/tranquil-cm4.img
```

正式发布时建议同时提供 `.sha256` 文件，并在发布说明中记录镜像生成时间、源代码提交、目标平台和已验证的启动方式。

## 使用 `tranquil-virt.img` 启动 QEMU virt

推荐优先使用内核仓库中的启动脚本。`run_qemu_virt.sh` 会自动完成构建、生成 `boot.img`、`system.img`、`user.img`、组装 `tranquil-virt.img` 并启动 QEMU。

```bash
cd /Users/neo/kernel
source env_setup.sh
./run_qemu_virt.sh
```

当前 QEMU 脚本会把 `out/tranquil-virt.img` 作为 raw VirtIO block 设备挂入虚拟机：

```bash
-drive if=none,format=raw,file=./out/tranquil-virt.img,id=disk
-device virtio-blk-device,drive=disk,bus=virtio-mmio-bus.3
```

如果已经取得 `tranquil-virt.img`，可将其放在仓库 `out/` 目录或脚本期望的位置，再复用 QEMU 启动脚本。直接手写 QEMU 参数时，应确保机器模型、CPU、内存、设备树、显示后端、VirtIO 设备和串口参数与 `platform/QemuVirt/scripts/run.sh` 保持一致，否则可能出现图形输出缺失、块设备不可见或早期启动中断。

## 烧录 `tranquil-cm4.img`

烧录前务必确认目标设备。`dd` 会覆盖目标磁盘内容，写错设备可能破坏宿主机磁盘或其他外接介质。

### 自动 CM4 流程

仓库中的 `run_board_cm4.sh` 当前只调用 `platform/CM4/scripts/flash.sh`。该脚本会自动执行：

1. 调用 `make_all_img.sh` 构建所有 ELF、`boot.img`、`system.img`、`user.img` 和 `tranquil-cm4.img`。
2. 运行 `platform/CM4/tools/rpi/rpiboot`。
3. 通过 `diskutil` 查找新增的外接 USB removable 设备。
4. 使用 raw 设备路径 `/dev/rdiskN` 写入 `out/tranquil-cm4.img`。
5. 写入完成后卸载并弹出设备。

```bash
cd /Users/neo/kernel
source env_setup.sh
./run_board_cm4.sh
```

### macOS 手动写入

1. 插入 SD 卡，或通过 CM4 eMMC mass-storage 模式暴露存储设备。
2. 使用 `diskutil list` 确认目标磁盘编号。

```bash
diskutil list
```

3. 卸载整盘并写入镜像。将 `diskN` 替换为实际磁盘编号。

```bash
diskutil unmountDisk /dev/diskN
sudo dd if=downloads/tranquil-cm4.img of=/dev/rdiskN bs=4m status=progress conv=sync
sync
diskutil eject /dev/diskN
```

### Linux 手动写入

1. 插入目标介质后，用 `lsblk` 或 `dmesg` 确认设备名。

```bash
lsblk
```

2. 将 `/dev/sdX` 替换为实际整盘设备。不要写入分区节点，例如 `/dev/sdX1`。

```bash
sudo umount /dev/sdX*
sudo dd if=downloads/tranquil-cm4.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

对于 eMMC、NVMe 或 SD 控制器，设备名可能是 `/dev/mmcblk0`、`/dev/nvme0n1` 或其他形式。请以 `lsblk` 显示的整盘设备为准。

## 启动后验证

启动后建议按以下顺序确认系统状态：

1. 串口日志：确认 bootloader、hypervisor、kernel 和 SystemDaemon 均完成初始化。
2. 内核对象：确认 capability root、scheduler、IRQ/timer 和基础驱动注册流程完成。
3. 图形输出：QEMU virt 与 Pi4/CM4 图形目标应出现 800x480 系统画布。
4. 用户态服务：确认 FsMgr、DevMgr、WindowMgr、AppMgr 等服务注册成功。
5. 应用启动：确认 launcher、settings、files 或 monitor 等用户应用能够启动。

若系统无法启动，优先检查镜像完整性、写入目标是否为整盘设备、CM4 boot 模式跳线、串口连接和 QEMU 参数。
