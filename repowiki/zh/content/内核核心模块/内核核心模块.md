## 定位

TranquilOS 的 `Kernel` 是运行在 AArch64 EL1 的微内核核心。它不把文件系统、设备管理、网络、图形窗口或应用管理放进内核，而是保留地址空间、调度上下文、中断、IPC、Upcall、Capability、定时器、系统调用和少量设备控制能力。用户态系统服务通过 Capability 和系统调用取得资源并组合出完整操作系统。

顶层构建目标由 [sys/BUILD.gn](file://sys/BUILD.gn) 组织，内核本体由 `sys/kernel/BUILD.gn` 编译为 `Kernel`，并依赖 `systemd:SystemDaemon`。当前内核版本宏在 `sys/BUILD.gn` 中定义为 `1.6.1`，平台链接脚本来自 `platform/$platform/linker/kernel.lds`。

## 源码组织

当前内核源码已经从早期文档中的 `kernel/`、`boot/` 单目录结构迁移到 `sys/kernel/`：

| 目录 | 职责 |
| --- | --- |
| `arch/arm64` | EL1 入口、异常向量、上下文切换、MMU、TLB、cache、原子操作与回溯支持 |
| `mm` | 启动期物理内存、页结构表、稀疏内存、地址空间与页表映射 |
| `capability` | CNode、VSpace、XContext、SContext、Timer、IRQ、IPC Endpoint、Upcall Endpoint 等对象能力 |
| `ipc` / `upcall` | 同步 IPC、弹性 IPC、IPC 端点池和用户态回调端点 |
| `schedule` / `context` | 每 CPU 调度管理、调度上下文、执行上下文和用户态切换 |
| `interrupt` / `timer` | IRQ 管理、用户态 IRQ、tick timer、RTC、timer manager 与定时器容器 |
| `device` / `drivers` | 设备树解析、设备注册、PL011、GICv2/v3、Generic Timer、PL031、PSCI、PMU、Mali、DMA 等驱动 |
| `syscall` | fastcall、兼容系统调用与内核系统调用入口 |
| `systemd` | 第一个 EL0 系统进程，承接后续用户态服务启动 |

## 初始化链路

系统镜像由平台脚本把 `Boot`、`Hypervisor`、`Kernel`、`SystemDaemon` 和 ramdisk 写入 boot image。运行时控制流通常为：

```text
Bootloader / Boot (EL1)
  -> Hypervisor (EL2, 可选目标)
     -> Kernel (EL1)
        -> SystemDaemon (EL0)
           -> Init / Devmgr / Fsmgr / Idle
           -> Zygote
           -> OS framework services
           -> applications and SystemUI
```

内核启动后会完成 AArch64 基础设施、设备树、早期内存、设备、IRQ、定时器、调度器、Capability 根对象和 `SystemDaemon` 上下文初始化。之后内核通过调度器进入用户态，把系统策略交给 EL0 服务。

## 关键子系统

### 内存与地址空间

`sys/kernel/mm` 提供 boot page allocator、page struct table、sparse memory、address space 和虚拟内存映射能力。内核负责建立基础页表、管理内核对象所需页资源，并通过 VSpace Capability 向用户态暴露受控映射操作。

### 调度与上下文

`schedule/sched_mgr.c` 负责每 CPU 调度器实例，`context/scontext.c` 与 `context/xcontext.c` 分别描述调度上下文与执行上下文。当前构建仍包含 FIFO 调度框架，但调度入口已经具备按框架扩展的结构，适合后续引入优先级、实时或交互式策略。

### IPC、Upcall 与系统调用

内核提供 IPC endpoint、IPC endpoint pool、elastic IPC 和 Upcall endpoint。同步服务调用、异步通知、异常上报以及用户态服务间协作都围绕这些机制展开。`syscall` 目录提供统一入口，Capability 调用由 `capability/capability.c` 分发到具体对象实现。

### 中断、定时器与设备

IRQ manager 把硬件中断映射为内核可管理对象，并可通过 IRQ Capability 授权给用户态。Timer manager 结合 Generic Timer、RTC 和定时器容器，为调度 tick、超时、用户态 timer capability 提供基础。

### Capability 安全边界

内核对象不直接暴露指针给用户态，而是通过 CNode 中的 capability reference 访问。对象类型和方法号共同决定可执行操作，权限位用于约束复制、调用、映射、控制等能力。

## 与用户态的边界

TranquilOS 的核心工程边界是：内核提供机制，用户态服务实现策略。`SystemDaemon` 是第一层用户态根服务，随后 `Init`、`Devmgr`、`Fsmgr` 以及 `os/base`、`os/framework` 中的服务扩展出设备、文件系统、进程派生、窗口、音频、输入、应用、字体、状态和时间管理。

因此，阅读内核代码时应把 `sys/kernel` 与 `sys/uapps`、`sys/ulibs` 一起看：内核定义对象和调用语义，用户态库封装调用，系统服务负责资源编排。

## 维护建议

- 修改内核对象时，同时检查 `sys/ulibs/include/libkernel` 中的用户态 ABI。
- 修改启动或镜像布局时，同时检查 `platform/*/scripts/make_boot_img.sh` 和链接脚本。
- 新增用户态可见对象时，应补齐 Capability 类型、方法分发、权限检查、用户态头文件和最小调用样例。
- 调整调度、IPC、中断路径后，至少在 QEMU Virt 上完成 `run_qemu_virt.sh` 全链路启动验证。
