## 环境要求

当前项目使用 GN/Ninja 组织构建，AArch64 交叉编译链生成裸机/用户态 ELF，QEMU 用于本地虚拟平台运行。macOS 上的镜像脚本还依赖 `e2fsprogs`，路径通常为 `/opt/homebrew/opt/e2fsprogs/sbin/mke2fs`。

建议开发环境具备：

- `gn`、`ninja`
- AArch64 ELF 工具链与 `objcopy`
- `qemu-system-aarch64`
- `e2fsprogs`
- Python 3，用于 IDL 生成脚本和测试

## 常用构建路径

QEMU Virt 推荐入口：

```bash
./run_qemu_virt.sh
```

它会依次执行：

1. `platform/QemuVirt/scripts/build.sh`
2. `make_boot_img.sh`
3. `make_system_img.sh`
4. `make_user_img.sh`
5. `make_all_img.sh`
6. `run.sh`

单独构建时可使用：

```bash
gn gen out --args="platform=\"QemuVirt\""
ninja -C out
```

## QEMU 调试参数

`platform/QemuVirt/scripts/run.sh` 默认启动 `qemu-system-aarch64`，使用 `virt` machine、GICv2、HVF 加速、4 核、2G 内存、virtio block、ramfb 和串口/monitor 后端。

脚本支持环境变量：

- `QEMU_DISPLAY_BACKEND`
- `QEMU_SERIAL_BACKEND`
- `QEMU_MONITOR_BACKEND`

这使开发者可以在无图形、串口日志、monitor 调试或 GUI 运行之间切换。

## IDL 工具

`tools/idl_gen.py` 和 `tools/idl_gen_action.py` 用于生成 IPC wrapper。`SystemDaemon` 的 systemd IPC 和 name service IPC 都通过 GN action 调用该工具生成服务端/客户端代码。

相关测试位于：

```bash
python3 tools/tests/test_idl_gen.py
```

修改 IDL 语法或生成逻辑时，应优先运行该测试，再进行完整系统构建。

## 日志与排错

- 启动早期问题：优先查看串口输出、PL011 控制台和 boot image 偏移。
- 内核异常：检查 `sys/kernel/exception`、`arch/arm64/exception.c`、coredump 和 backtrace 输出。
- IPC/服务问题：检查 IDL wrapper、name service 注册、端点 Capability 是否正确传递。
- 镜像问题：检查 `out/boot.img`、`out/system.img`、`out/user.img` 和最终 raw image 的分区布局。
- CM4 烧录问题：先确认 `rpiboot` 成功，再确认 `diskutil` 识别的新外置磁盘是否是目标设备。

## 建议验证顺序

1. `gn gen` + `ninja -C out` 通过。
2. QEMU Virt 可进入 SystemDaemon 和基础服务。
3. system image 中的 framework 服务和 SystemUI 可启动。
4. 修改平台或驱动后，再验证 Pi/CM4 目标。
