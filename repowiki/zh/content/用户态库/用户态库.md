## 定位

TranquilOS 的用户态库分为两层：`sys/ulibs` 面向系统启动、内核 ABI 和基础用户态程序；`os/libs` 面向完整 OS 图形、网络、媒体和应用运行环境。前者更接近微内核 ABI，后者更接近应用框架依赖。

## sys/ulibs

`sys/ulibs` 使用 `-nostdlib`、`-nostdinc` 和 `--no-standard-libraries` 构建，说明基础用户态不依赖宿主标准库。它提供：

| 库 | 职责 |
| --- | --- |
| `libc` | 最小 C 运行时、字符串、格式化输出、入口/退出支持 |
| `libcrt` | 用户态启动与运行时辅助 |
| `libalgorithm` | 动态数组、FIFO、红黑树、最小堆等基础数据结构 |
| `libfdt` | Flattened Device Tree 解析 |
| `libsync` | 原子、mutex、spinlock 等同步原语 |
| `libsyscall` | 系统调用和 POSIX 风格封装 |
| `libsystem` | systemd、IPC、进程加载、音频、蓝牙、WLAN 等系统接口封装 |

`sys/ulibs/include/libkernel` 是用户态访问内核对象的关键 ABI 层，包含 capability、capcall、types 和 upcall 定义。修改内核 capability 或系统调用语义时，必须同步检查这里。

## 运行时组合

[sys/ulibs/BUILD.gn](file://sys/ulibs/BUILD.gn) 定义了几个常用运行时组合：

- `uapp_runtime`：包含基本 `libc_exit` 与 `uapp_init`。
- `uapp_runtime_with_syscall`：在基础运行时上加入 syscall 支持。
- `uapp_runtime_with_posix`：当前同样基于 syscall，面向 POSIX 风格接口。

基础 UAPPS 和 `SystemDaemon` 会按需要选择这些组合，确保早期用户态足够小、依赖明确。

## os/libs 与第三方库

`os/libs` 为完整 OS 层提供更高阶能力，常见模块包括：

- `libfreetype`：字体渲染支持。
- `libhttp`：HTTP 客户端/网络应用辅助。
- `libjson`：JSON 解析封装。
- `liblvgl`：LVGL 图形界面库适配。
- `liblwip`：lwIP 网络协议栈适配。
- `libmbedtls`：TLS/密码学支持。
- `libminimp3`：MP3 解码支持。
- `libpng`：PNG 图像支持。

第三方源码位于 `os/thrid_party`，包括 cJSON、freetype、lodepng、lvgl、lwip、mbedtls、minimp3、musl 等。目录名保留当前仓库拼写 `thrid_party`，文档和脚本引用时应使用实际路径。

## 维护建议

- ABI 头文件变更必须和内核、systemd、基础服务一起验证。
- `sys/ulibs` 不应轻易引入大型第三方依赖，以免扩大早期启动面。
- GUI、网络、媒体相关依赖应优先放在 `os/libs` 层。
- 新增库应补齐 GN target、public include、依赖关系和最小使用方，避免只提交源码目录。
