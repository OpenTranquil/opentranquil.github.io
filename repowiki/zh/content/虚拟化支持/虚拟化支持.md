## 定位

TranquilOS 包含一个面向 AArch64 EL2 的可选 Hypervisor 目标。它由 `sys/virt/BUILD.gn` 构建为 `Hypervisor`，与 `Boot`、`Kernel`、`SystemDaemon` 一起被写入平台 boot image。虚拟化层的目标不是替代微内核，而是在更高异常级提供 VM、VCPU、Stage-2 映射、EL2 异常处理和 hypcall 基础。

## 组件结构

| 模块 | 职责 |
| --- | --- |
| `hypervisor.c` | EL2 主控制逻辑 |
| `vm.c` | 虚拟机对象管理 |
| `vcpu.c` | 虚拟 CPU 状态与切换 |
| `hypcall/hypcall.c` | EL1 与 EL2 之间的 hypercall/hypcall 通道 |
| `mm/vmem.c` | Hypervisor 虚拟内存 |
| `mm/pgtable_stage2.c` | Stage-2 页表支持 |
| `exceptions_el2.c` | EL2 异常处理 |
| `interrupt/irq_mgr.c` | EL2 中断管理 |
| `drivers/arm-gic/gicv2.c` | 虚拟化层使用的 GICv2 支持 |
| `drivers/arm-uart/pl011.c` | EL2 控制台输出 |

Hypervisor 构建复用 `sys/ulibs` 中的 `libc`、`printf`、`libfdt`，并复用内核的部分 AArch64 CPU 与设备树代码。

## 与内核的关系

`sys/kernel/drivers/hvdriver/hypervisor.c` 是内核侧的 Hypervisor 桥接驱动。内核仍运行在 EL1，负责微内核对象、用户态服务和调度；Hypervisor 在 EL2 处理虚拟化相关控制面。平台 boot image 同时包含 `Hypervisor` 和 `Kernel`，具体启用路径取决于平台启动代码与运行参数。

## 镜像与运行

QEMU Virt 的 boot image 脚本会把 Hypervisor 放入固定偏移：

- `Boot`：boot image 起始区域。
- `virt.dtb`：设备树。
- `Hypervisor`：EL2 目标。
- `Kernel`：EL1 微内核。
- `SystemDaemon`：EL0 根服务。
- ramdisk：`Devmgr`、`Fsmgr`、`Idle`、`Init` 等基础程序。

当前 `platform/QemuVirt/scripts/run.sh` 默认使用 `-machine virt,gic-version=2,virtualization=off,accel=hvf`。这说明 QEMU Virt 默认运行链路主要用于微内核和用户态系统验证；如果要验证 EL2 虚拟化能力，需要同步审视 QEMU 参数、平台启动路径和 Hypervisor 初始化日志。

## 开发建议

- 修改 EL2 页表、异常或 VCPU 逻辑时，应同时检查 `include/mm/pgtable_stage2.h`、`include/vcpu.h`、`include/vm.h`。
- hypcall ABI 变化需要同步内核侧 `hvdriver` 和用户态/内核调用方。
- 虚拟化功能涉及异常级切换，调试时应保留串口日志并优先在 QEMU 中复现。
- 不应把普通 OS 服务策略放入 Hypervisor；EL2 只承载需要最高异常级隔离或硬件虚拟化语义的机制。
