## 定位

TranquilOS 的平台适配由 GN 参数 `platform`、平台链接脚本、DTB/DTS、镜像制作脚本和运行/烧录脚本共同完成。内核、Hypervisor、SystemDaemon 和用户态程序共用同一套源码，但不同平台使用自己的地址布局、设备树、固件文件和镜像格式。

## 支持平台

| 平台 | 主要用途 | 关键脚本 |
| --- | --- | --- |
| `QemuVirt` | 本地 AArch64 虚拟机开发与回归验证 | `platform/QemuVirt/scripts/build.sh`、`make_all_img.sh`、`run.sh` |
| `CM4` | Raspberry Pi Compute Module 4 实机镜像与烧录 | `platform/CM4/scripts/make_all_img.sh`、`flash.sh` |
| `Pi3b` | Raspberry Pi 3B QEMU/板级适配 | `platform/Pi3b/scripts/*` |
| `Pi4b` | Raspberry Pi 4B QEMU/板级适配 | `platform/Pi4b/scripts/*` |

## 构建参数

平台构建脚本通常执行：

```bash
gn gen out --args="platform=\"QemuVirt\""
ninja -C out
```

`platform` 参数影响：

- `platform/$platform/linker/*.lds`：Boot、Hypervisor、Kernel、SystemDaemon 的链接地址。
- `platform/$platform/dtb/*.dtb`：运行时设备树。
- `platform/$platform/scripts/*.sh`：boot/system/user/all 镜像制作和运行方式。
- `build/platform` 相关宏：平台特定编译定义。

## 镜像布局

QEMU Virt 和 CM4 都会生成 raw 镜像，但内容组织不同：

- `QemuVirt` 生成 `out/tranquil-virt.img`，包含 boot 分区、system 分区和 user 分区。
- `CM4` 生成 `out/tranquil-cm4.img`，boot 分区包含树莓派固件、`boot.img` 和 `bcm2711-rpi-cm4.dtb`，后续分区为 system/user。

QEMU Virt 的 `make_boot_img.sh` 会把 `Boot`、`virt.dtb`、`Hypervisor`、`Kernel`、`SystemDaemon` 和 ramdisk 写入固定偏移。CM4 的 `make_all_img.sh` 会额外复制 Raspberry Pi 固件并生成可烧录到 eMMC/USB mass storage 的镜像。

## 运行与烧录

- `./run_qemu_virt.sh`：完整构建 QEMU Virt 镜像并启动 `qemu-system-aarch64`。
- `./run_qemu_pi3b.sh`、`./run_qemu_pi4b.sh`：分别运行 Pi3b/Pi4b 平台链路。
- `./run_board_cm4.sh`：调用 CM4 flash 脚本，使用 `rpiboot` 进入 USB mass storage，再用 `dd` 写入 `tranquil-cm4.img`。

CM4 烧录脚本会检测新出现的外置可移动磁盘，并使用 `/dev/rdiskN` 写入镜像。执行前必须确认目标设备，避免覆盖宿主机磁盘。

## 维护建议

- 新平台至少需要 `linker/`、`dts`/`dtb`、`scripts/build.sh`、boot/system/user 镜像脚本。
- 平台地址布局变化必须同步更新链接脚本、设备树和镜像偏移。
- QEMU 运行参数应与 GIC 版本、CPU、内存、virtio 设备和显示后端保持一致。
- 修改镜像脚本后，建议同时验证网站下载页和 repowiki 下载烧录页中的说明。
