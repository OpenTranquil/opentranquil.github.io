## 总体结构

TranquilOS 使用 GN 生成 Ninja 构建图。顶层 `BUILD.gn` 只有一个核心入口：

```gn
group("OS") {
  deps = [
    "//sys:sys",
    "//os:os",
  ]
}
```

`//sys:sys` 构建可信计算基，包括 bootloader、hypervisor 和 kernel；`//os:os` 构建系统会话层，包括早期用户态服务、zygote、framework services、system UI 和用户应用。

## `sys` 构建目标

`sys/BUILD.gn` 定义低层系统配置和 `group("sys")`。该组目前依赖：

- `//sys/boot:Boot`
- `//sys/virt:Hypervisor`
- `//sys/kernel:Kernel`

SystemDaemon 虽然位于 `sys/kernel/systemd`，但它作为 kernel 构建链路中的特权 EL0 产物生成，并在 `make_boot_img.sh` 中被 objcopy 为 `out/systemd.img` 写入 `boot.img`。

`sys/BUILD.gn` 同时定义了几组编译配置：

- `kernel_compile_flags`：面向 EL1 kernel，使用 `-mcpu=cortex-a72+nofp`、严格对齐和 frame pointer。
- `virt_compile_flags`：面向 EL2 hypervisor。
- `trustee_compile_flags`：保留给 trusted execution stub。
- `systemd_compile_flags`：面向 privileged EL0 SystemDaemon。
- `kernel_version_defines`：当前为 `1.6.1`。

## `os` 构建目标

`os/BUILD.gn` 定义 `group("os")`，并把 OS 用户态全部纳入同一构建图。当前包含：

- `//sys/uapps:UAPPS`
- `//os/base/zygote:Zygote`
- `//os/base/netmgr:Netmgr`
- `//os/base/btmgr:Btmgr`
- `//os/framework/windowmgr:Windowmgr`
- `//os/framework/mmimgr:Mmimgr`
- `//os/framework/appmgr:Appmgr`
- `//os/framework/audiomgr:Audiomgr`
- `//os/framework/fontmgr:Fontmgr`
- `//os/framework/statemgr:Statemgr`
- `//os/framework/timemgr:TimeMgr`
- `//os/framework/agentmgr:Agentmgr`
- `//os/apps/...` 下的 AI、calendar、calculator、clock、files、memo、monitor、music、NES、settings、whiteboard 和 system UI 组件。

`os_version_defines` 当前声明 OS 版本为 `1.8.43`。普通用户态和 GUI 用户态分别通过 `userspace_compile_flags` 与 `userspace_gui_compile_flags` 管理，GUI 配置会定义 `LV_CONF_INCLUDE_SIMPLE`。

## 平台参数

平台由 GN args 传入，例如 QEMU virt：

```bash
gn gen out --args='platform="QemuVirt"'
ninja -C out
```

平台参数会影响链接脚本、设备树、平台配置和运行脚本。当前平台目录包括：

- `platform/QemuVirt`
- `platform/Pi3b`
- `platform/Pi4b`
- `platform/CM4`

## 镜像生成流水线

QEMU virt 的完整镜像生成由平台脚本串联完成：

```text
build.sh
  -> gn gen out --args="platform=\"QemuVirt\""
  -> ninja -C out

make_boot_img.sh
  -> objcopy Boot/Hypervisor/Kernel/SystemDaemon
  -> copy devmgr/fsmgr/idle/init into images/ramdisk
  -> pack ramdisk.cpio
  -> write fixed-offset boot.img

make_system_img.sh
  -> strip zygote, framework services, system UI and apps
  -> stage images/system
  -> create ext2 system.img

make_user_img.sh
  -> stage images/user
  -> create ext2 user.img

make_all_img.sh
  -> create raw disk image
  -> write MBR
  -> create FAT32 boot partition
  -> write ext2 system partition
  -> write ext2 user partition
```

## `boot.img` 布局

`make_boot_img.sh` 创建 64 MB `out/boot.img`，按 4096 字节块写入固定偏移：

| seek | 内容 | 大小 |
| --- | --- | --- |
| `0` | `loader.img` | 8 MB |
| `2048` | `virt.dtb` | 8 MB |
| `4096` | `hypervisor.img` | 16 MB |
| `8192` | `kernel.img` | 16 MB |
| `12288` | `systemd.img` | 8 MB |
| `14336` | `ramdisk.cpio` | 8 MB |

ramdisk 当前包含 `devmgr.elf`、`fsmgr.elf`、`idle.elf` 和 `init.elf`。这些服务需要在 `system.img` 可用之前完成最早期用户态职责。

## `system.img` 与 `user.img`

`system.img` 默认 128 MB，ext2，标签为 `SYSTEM`。脚本会从 `images/system` 创建 staging 目录，然后复制 strip 后的 zygote、framework services、system UI 和应用 ELF。

`user.img` 默认 64 MB，ext2，标签为 `USER`。脚本从 `images/user` 创建用户分区模板，当前包含 AI 配置、NES ROM、音乐和图片等示例内容。

## 原始磁盘镜像

`make_all_img.sh` 会把 boot、system、user 三个镜像组装为 `out/tranquil-virt.img`：

| 分区 | 类型 | 内容 |
| --- | --- | --- |
| P1 | FAT32 | `boot.img` |
| P2 | ext2 | `system.img` |
| P3 | ext2 | `user.img` |

CM4 的 `make_all_img.sh` 使用同类三分区模型，但还会把平台 firmware 和 `bcm2711-rpi-cm4.dtb` 复制到 FAT32 boot 分区。
