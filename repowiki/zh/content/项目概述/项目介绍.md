## 定位

TranquilOS 是一个面向 AArch64 的 capability-based 微内核操作系统。当前代码将系统拆分为两条主线：`sys/` 提供可信计算基、启动链、EL2 hypervisor、EL1 microkernel、SystemDaemon、基础用户态服务和低层库；`os/` 提供面向用户会话的 zygote、framework services、图形系统、应用管理、音频、字体、状态、时间、AI agent 以及用户应用。

顶层构建目标 `group("OS")` 同时依赖 `//sys:sys` 和 `//os:os`。这意味着 TranquilOS 不是单一 kernel binary，而是由 bootloader、hypervisor、kernel、SystemDaemon、ramdisk、system image、user image 和多个 EL0 服务共同组成的完整系统镜像。

## 运行时层次

当前代码中的运行时层次如下：

```text
Bootloader (EL1)
  -> Hypervisor (EL2, optional)
     -> Microkernel (EL1)
        -> SystemDaemon (privileged EL0)
           -> init
              -> zygote
                 -> framework services
                    -> user applications
```

SystemDaemon 承担传统内核中更高层的资源管理职责，包括进程、内存、IPC namespace 和虚拟化管理。`sys/uapps` 中的 `init`、`idle`、`devmgr`、`fsmgr` 作为启动早期的基础服务进入 ramdisk；`os/base` 与 `os/framework` 中的服务随后从 `system.img` 加载，形成图形会话和应用运行环境。

## 代码结构

当前源码的关键目录如下：

| 目录 | 职责 |
| --- | --- |
| `sys/boot` | bootloader 与早期启动。 |
| `sys/virt` | EL2 Type-1 hypervisor、VM/VCPU/PCPU、stage-2 地址转换和 hypcall。 |
| `sys/kernel` | EL1 微内核，包含 capability、IPC、MMU、调度、IRQ、timer、futex、upcall、module、trace、console 和驱动框架。 |
| `sys/kernel/systemd` | 特权 EL0 SystemDaemon，包含 `procmgr`、`memmgr`、`ipcmgr`、`virtmgr`。 |
| `sys/uapps` | 启动早期用户态服务，包括 `idle`、`init`、`devmgr`、`fsmgr`。 |
| `sys/ulibs` | 低层用户态库，包括 libc、CRT、syscall wrapper、systemd client、libfdt、同步与算法库。 |
| `os/base` | zygote、netmgr、btmgr 等 OS 基础用户态组件。 |
| `os/framework` | windowmgr、mmimgr、appmgr、audiomgr、fontmgr、statemgr、timemgr、agentmgr 等 framework services。 |
| `os/apps` | AI、calendar、calculator、clock、files、memo、monitor、music、NES、settings、whiteboard 和 system UI 组件。 |
| `platform` | QemuVirt、Pi3b、Pi4b、CM4 的设备树、链接脚本、固件、构建和运行脚本。 |
| `images` | ramdisk、system image、user image 的模板内容。 |

## 当前功能覆盖

代码实现覆盖以下系统能力：

- AArch64 exception model、MMU、SMP、per-CPU scheduler 和抢占式调度。
- capability-based access control，覆盖 CNode、VSpace、Endpoint、Timer、Futex、IRQ 等对象。
- migrating-thread synchronous IPC、elastic IPC endpoint pool、fastcall 和 upcall。
- EL2 hypervisor，包含 stage-2 page table、VM/VCPU/PCPU、vGIC、vTimer、vPMU 和 hypcall。
- SystemDaemon 作为 privileged EL0 root service，承接进程、内存、IPC namespace 和 VM 生命周期。
- devmgr、fsmgr、netmgr、windowmgr、mmimgr、appmgr、audiomgr、fontmgr、statemgr、timemgr、agentmgr、imemgr 等服务。
- LVGL、FreeType、PortableGL、lwIP、mbedTLS、musl 等第三方组件在 `os/thrid_party` 下进入用户态图形、字体、网络和运行库路径。

## 构建与启动目标

主要开发目标是 QEMU virt。`run_qemu_virt.sh` 会完成构建、生成 `boot.img`、`system.img`、`user.img`，再组装 `tranquil-virt.img` 并启动 QEMU。QEMU 配置使用 4 核 SMP、2 GB RAM、HVF 加速、GICv2、ramfb、VirtIO input/network/block/sound 和串口控制台。

除 QEMU virt 外，代码还保留 Pi3b、Pi4b 和 CM4 平台路径。Pi3b/Pi4b 用于 QEMU 平台验证；CM4 通过 `platform/CM4/scripts/flash.sh` 构建 SD/eMMC 镜像并借助 `rpiboot` 写入真实硬件。
