## 当前系统分层

TranquilOS 当前代码按 `sys/` 与 `os/` 两个大层组织。`sys/` 是可信计算基，包含 bootloader、EL2 hypervisor、EL1 microkernel、SystemDaemon、早期用户态服务和低层用户态库；`os/` 是完整用户会话，包含 zygote、netmgr、btmgr、framework services、系统 UI 与用户应用。

运行路径可以概括为：

```text
Bootloader (EL1)
  -> Hypervisor (EL2, optional)
     -> Microkernel (EL1)
        -> SystemDaemon (privileged EL0)
           -> init
              -> zygote
                 -> framework services
                    -> user applications
```

这一路径体现了项目的核心设计：内核保持对象分发、调度、IPC、异常、中断、定时器、futex、upcall、console 和低层驱动等最小职责；进程、内存、IPC namespace、VM 生命周期、设备、文件系统、图形、应用和 AI agent 等能力迁移到 EL0 服务中。

## 构建边界与运行边界

顶层 `BUILD.gn` 中的 `group("OS")` 同时依赖 `//sys:sys` 和 `//os:os`。因此构建产物天然对应运行时分层：

| 构建区域 | 主要产物 | 运行职责 |
| --- | --- | --- |
| `sys/boot` | `Boot` | 早期启动、设备树和镜像交接。 |
| `sys/virt` | `Hypervisor` | EL2 虚拟化、stage-2 地址转换、VM/VCPU 管理。 |
| `sys/kernel` | `Kernel` | EL1 微内核核心机制。 |
| `sys/kernel/systemd` | `SystemDaemon` | privileged EL0 root service。 |
| `sys/uapps` | `Init`、`Idle`、`Devmgr`、`Fsmgr` | ramdisk 早期用户态服务。 |
| `os/base` | `Zygote`、`Netmgr`、`Btmgr` | OS 会话启动与基础服务。 |
| `os/framework` | Window/App/Audio/Font/State/Time/Agent 等服务 | framework service 层。 |
| `os/apps` | 用户应用和 system UI | 面向用户的应用层。 |

## 镜像边界

QEMU virt 与 CM4 平台都使用由多个镜像组成的启动介质：

- `boot.img`：固定偏移启动容器，包含 bootloader、DTB、hypervisor、kernel、SystemDaemon 和 ramdisk。
- `system.img`：ext2 系统分区，包含 zygote、framework services、system UI 和应用 ELF。
- `user.img`：ext2 用户分区，包含用户数据模板。
- `tranquil-virt.img` / `tranquil-cm4.img`：raw disk image，包含 FAT32 boot、ext2 system、ext2 user 三个分区。

这个结构让启动前半段不依赖文件系统，启动后半段通过 FsMgr 和 zygote 从系统分区加载更大的服务与应用。

## 接口原则

系统内的服务边界主要通过 capability、IPC endpoint、共享内存和 IDL 生成代码连接。服务调用不应绕过 SystemDaemon 和命名空间机制直接假设全局资源；图形、文件系统、网络、应用生命周期和 AI agent 等服务都应作为独立 EL0 组件在同一套 IPC/SHM 约束下协作。
