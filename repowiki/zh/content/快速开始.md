## 环境准备

TranquilOS 使用 GN/Ninja 构建，并依赖 AArch64 交叉工具链。默认路径使用 `toolchains/aarch64-elf-12.2.0-Darwin-arm64`，适合 macOS ARM64 主机；其他工具链配置由 `build/toolchain/BUILD.gn` 和 GN args 控制。

```bash
cd /Users/neo/kernel
source env_setup.sh
```

`env_setup.sh` 会为构建脚本提供仓库根路径、GN/Ninja 和交叉编译工具链路径。首次构建前应确认 QEMU 和 Homebrew e2fsprogs 可用，因为系统镜像和用户镜像由平台脚本使用 `mke2fs` 生成 ext2 文件系统。

## QEMU virt 一键运行

主要开发入口是：

```bash
source env_setup.sh
./run_qemu_virt.sh
```

该脚本按顺序执行：

1. `platform/QemuVirt/scripts/build.sh`
2. `platform/QemuVirt/scripts/make_boot_img.sh`
3. `platform/QemuVirt/scripts/make_system_img.sh`
4. `platform/QemuVirt/scripts/make_user_img.sh`
5. `platform/QemuVirt/scripts/make_all_img.sh`
6. `platform/QemuVirt/scripts/run.sh`

因此，一键入口不仅编译 ELF，还会生成 `boot.img`、`system.img`、`user.img`，再组装包含三分区布局的 `out/tranquil-virt.img`，最后启动 QEMU。

## QEMU virt 运行参数

当前 QEMU virt 脚本使用以下主要参数：

- machine：`virt,gic-version=2,virtualization=off,accel=hvf`
- CPU：`host`
- SMP：4 cores
- RAM：2 GB
- kernel：`./out/boot.img`
- DTB：`platform/QemuVirt/dtb/virt.dtb`
- block device：`./out/tranquil-virt.img`
- display：ramfb，默认 `cocoa`
- input/network/sound：VirtIO tablet、keyboard、net、block、sound

可以通过环境变量覆盖显示、串口和 monitor 后端：

```bash
QEMU_DISPLAY_BACKEND=gtk ./run_qemu_virt.sh
QEMU_SERIAL_BACKEND=stdio ./run_qemu_virt.sh
QEMU_MONITOR_BACKEND=stdio ./run_qemu_virt.sh
```

## 其他平台

```bash
./run_qemu_pi3b.sh
./run_qemu_pi4b.sh
./run_board_cm4.sh
```

Pi3b 和 Pi4b 路径分别调用对应平台目录下的 build、image 和 run 脚本。CM4 入口当前只调用 `platform/CM4/scripts/flash.sh`，该脚本会构建镜像、启动 `rpiboot`、检测 CM4 mass-storage 设备并写入 `out/tranquil-cm4.img`。

## 手动构建

若只需要编译 ELF，可直接使用 GN/Ninja：

```bash
source env_setup.sh
gn gen out --args='platform="QemuVirt"'
ninja -C out
```

若要得到可启动镜像，仍需执行对应平台的 image 脚本。例如 QEMU virt：

```bash
./platform/QemuVirt/scripts/make_boot_img.sh
./platform/QemuVirt/scripts/make_system_img.sh
./platform/QemuVirt/scripts/make_user_img.sh
./platform/QemuVirt/scripts/make_all_img.sh
```

## 产物

| 产物 | 来源 | 说明 |
| --- | --- | --- |
| `out/Boot` | `sys/boot` | bootloader ELF。 |
| `out/Hypervisor` | `sys/virt` | EL2 hypervisor ELF。 |
| `out/Kernel` | `sys/kernel` | EL1 microkernel ELF。 |
| `out/SystemDaemon` | `sys/kernel/systemd` | privileged EL0 root service。 |
| `out/boot.img` | `make_boot_img.sh` | 固定偏移启动容器，包含 loader、DTB、hypervisor、kernel、SystemDaemon 和 ramdisk。 |
| `out/system.img` | `make_system_img.sh` | 128 MB ext2 系统分区，包含 zygote、framework services、system UI 和应用 ELF。 |
| `out/user.img` | `make_user_img.sh` | 64 MB ext2 用户分区，包含示例音乐、游戏、图片和 AI 配置文件。 |
| `out/tranquil-virt.img` | `make_all_img.sh` | QEMU virt 原始磁盘镜像，包含 FAT32 boot、ext2 system、ext2 user 三个分区。 |

## 常见问题

- 找不到 `mke2fs`：安装 Homebrew `e2fsprogs`，脚本默认读取 `/opt/homebrew/opt/e2fsprogs/sbin/mke2fs`。
- QEMU 无图形：确认 `-device ramfb` 已启用，并检查 `QEMU_DISPLAY_BACKEND`。
- 服务未启动：确认 `system.img` 已重新生成，否则修改后的 framework service ELF 不会进入系统分区。
- CM4 写入风险：写入前必须确认目标磁盘，`flash.sh` 会自动筛选外接 USB removable 设备，但仍应检查输出的设备名。
